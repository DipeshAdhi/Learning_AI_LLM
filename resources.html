Resources

Where to read next.

A short, checked list rather than a long one. Everything here is free to read, and each entry says who wrote it — because documentation from the company that built a model and a blog post about that model are not the same kind of evidence.

What the labels mean

  • Official — written and maintained by the people who build the thing. Correct by default; check the date, not the claim.
  • Community — collected by volunteers. Broad and genuinely useful, but nobody guarantees any single entry is current.

If a page here ever cites a company's own benchmark of its own product, it will say so plainly.

Phase 3

The Markdown files people keep

Since an assistant starts each session with no memory, the common fix is to write things down where it can read them again. Most projects settle on a handful of plain Markdown files at the repository root.

PROJECT.md holds what the project is and why. MEMORY.md keeps facts and decisions worth surviving. SUMMARY.md is a short record of a long conversation, loaded instead of replaying the whole thing. TASKS.md tracks what is done, what is next, and what is blocked.

Alongside them sits a skills folder: one file per capability, describing how a job should be done. The assistant reads only the titles until one matches, then opens that file. That is progressive disclosure, and it is why the red band in the homepage demo disappears.

Is this an official standard?

No. These filenames are a widely copied convention, not a specification, and different tools expect different names — some want CLAUDE.md, some read a memory-bank/ folder, some use none of this. Pick one scheme and keep it consistent inside a project; that matters far more than which names you chose.

a common layout

project/
├── README.md      for humans
├── PROJECT.md     what this is, and why
├── MEMORY.md      decisions worth keeping
├── SUMMARY.md     the long conversation, shortened
├── TASKS.md       done · next · blocked
├── CHANGELOG.md   what changed, when
├── prompts/
├── skills/
│   ├── coding.skill
│   ├── research.skill
│   └── writing.skill
└── docs/
