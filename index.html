    New here? What am I actually looking at?

    AI models read text in chunks called tokens — roughly three quarters of a word each. Everything the model can see at once has to fit in a fixed space called the context window, and you pay for every token you put in it, every single time you send a message. The red stripes are text that was sent and paid for on every turn without ever being useful. Phase 1 explains all of this slowly; Phase 2 shows you how to fix it.

    Illustrative figures, priced at $3 per million input tokens. Token counts are modelled, not measured — Phase 2 shows you how to measure your own.

    Why AI keeps forgetting.

    A language model has no memory of its own. Every message you send starts it from nothing — no recollection of yesterday's decision, no idea what you agreed an hour ago, no sense of which of your rules matter right now. Everything it appears to remember, something put back in front of it.

    Which means the real skill is not phrasing a clever question. It is deciding what gets loaded, in what order, and what gets dropped first when there is no more room. That is the part the tutorials skip, and it is where the difference between frustrating AI and useful AI actually lives.

    There is real machinery for it: instructions packaged as skills and opened only when they match; state written to files the assistant rereads when it wakes up; stable text placed first so it can be cached and paid for once; long histories compressed instead of forgotten. Each of those gets its own chapter here.

    Everything is a file

    The book comes with a repository, and the repository is half the point. Skills, memory templates, prompts, and evaluations are plain Markdown you can read, copy, and drop straight into a project of your own.

    Nothing here is a screenshot of a technique. If a chapter says a structure saves tokens, the structure is in the tree and you can run it yourself.
