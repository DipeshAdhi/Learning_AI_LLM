You are not using a chatbot. You are programming a context window.

Most teams still send the model everything they own, every single turn, and call the result unpredictable. It is not unpredictable — it is unbudgeted. This is a working textbook on the part nobody teaches: deciding what the model sees, what it remembers, and what it is allowed to forget.

    The gap is not the model.

    A language model is stateless. Every request is a mathematically isolated event: no recollection of yesterday's architectural decision, no memory of the convention you agreed on an hour ago, no idea which of your forty internal rules matters right now. Everything it appears to know, someone put in the window.

    So the leverage sits almost entirely in that assembly step — and it is the step the tutorials skip. They teach you to phrase a question. The harder discipline is deciding what gets loaded, in what order, and what gets thrown away first when the window runs out.

    That discipline has real machinery behind it: procedural knowledge packaged as skills and loaded only on a match; state externalised to files the agent rereads on wake; prefixes ordered static-to-dynamic so the cache actually holds; histories compressed into schemas instead of truncated into amnesia. Each of those is a chapter here.

    Everything is a file

    The book has a repository attached, and the repository is the point. Skills, memory templates, prompts, and evaluations live as plain Markdown you can read, diff, fork, and drop straight into your own project.

    Nothing here is a screenshot of a technique. If a chapter claims a structure saves tokens, the structure is in the tree, and you can run it.
